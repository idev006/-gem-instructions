# คู่มือสำหรับครู — Activity-Based Elementary Worksheet Generator

Version: 1.2.0

คู่มือนี้เขียนสำหรับ **ครูและผู้สร้างสื่อที่ไม่จำเป็นต้องเก่งเทคโนโลยี** คุณสามารถสั่งงานด้วยภาษาไทยธรรมดาได้ ไม่ต้องจำชื่อ Parameter และไม่ต้องเขียน Prompt แบบเทคนิค

## Gem นี้ช่วยอะไร

Gem ช่วยเปลี่ยนความต้องการของครูให้เป็นใบงานที่มีโครงสร้างชัดเจน โดยระบบจะ:

- ทำความเข้าใจระดับชั้นและเรื่องที่ต้องการฝึก
- สร้างโจทย์ให้เหมาะกับเด็ก
- ตรวจคำตอบและตรรกะทางคณิตศาสตร์ภายใน
- จัดกิจกรรมและภาพประกอบให้สัมพันธ์กัน
- วางแผนหน้า A4 และพื้นที่คำตอบ
- ตรวจภาษาไทยและจำนวนข้อ
- ป้องกันเฉลยหลุดเข้าใบงานนักเรียน
- สร้าง Blueprint และ Final Image Prompt พร้อมใช้

รุ่นปัจจุบันพัฒนาและทดสอบเชิงตรรกะมากที่สุดกับใบงานคณิตศาสตร์เรื่อง **เวลา** โดยเฉพาะการหาระยะเวลาจากเวลาเริ่มต้นและเวลาสิ้นสุด

---

# เริ่มใช้งานง่ายที่สุด

ครูควรบอกเพียง 3 อย่างเป็นขั้นต่ำ:

1. **ระดับชั้น**
2. **เรื่องหรือทักษะที่ต้องการฝึก**
3. **จำนวนข้อ**

ตัวอย่างสั้นที่สุด:

> ป.3 เรื่องหาระยะเวลา 10 ข้อ

แค่นี้ Gem ก็สามารถเติมค่าที่ปลอดภัยให้เองได้ เช่น A4 แนวตั้ง ขาวดำ มีกิจกรรมใกล้ตัว มีชื่อ/ชั้น/เลขที่ มีหมายเลขข้อ และไม่ใส่เฉลย

ถ้าข้อมูลสำคัญยังไม่พอจริง ๆ Gem จะถามเพียงคำถามสั้น ๆ ที่จำเป็น ไม่ควรถามครูเป็นรายการ Parameter ยาว ๆ

# อะไร “ต้องบอก” และอะไร “ไม่ต้องบอก”

## ต้องบอก 3 อย่าง

### 1. ระดับชั้น

ตัวอย่าง:

- ป.2
- ป.3
- ประถมศึกษาปีที่ 4

ระดับชั้นมีผลต่อความยาก ภาษา และพื้นที่เขียนของเด็ก

### 2. เรื่องหรือทักษะ

ตัวอย่าง:

- การหาระยะเวลา
- เวลาเริ่มต้นและเวลาสิ้นสุด
- การบอกระยะเวลาเป็นชั่วโมงและนาที

### 3. จำนวนข้อ

ตัวอย่าง:

- 8 ข้อ
- 10 ข้อ
- 12 ข้อ

จำนวนข้อมีผลต่อขนาดตัวอักษร พื้นที่ตอบ และจำนวนหน้า จึงไม่ควรปล่อยให้ระบบเดาเองในงาน production

# สิ่งที่ไม่จำเป็นต้องบอก

ถ้าครูไม่ระบุ Gem จะใช้ค่าเริ่มต้นหรือเลือกให้ตามความเหมาะสม เช่น:

- วิชา: คณิตศาสตร์ เมื่อหัวข้อเป็นเรื่องเวลา
- ภาษา: ไทย
- ระดับความยาก: AUTO ตามชั้นและทักษะ
- กระดาษ: A4
- แนวกระดาษ: แนวตั้ง
- สี: ขาวดำ
- ส่วนหัว: ชื่อ / ชั้น / เลขที่
- หมายเลขข้อ: มี
- เฉลย: ไม่มี
- ธีมกิจกรรม: ชีวิตประจำวันของเด็ก
- ภาพประกอบ: ไอคอนเส้นง่าย ๆ ที่ตรงกับกิจกรรม
- แบ่งหน้าอัตโนมัติ: เปิด
- การข้ามเที่ยงคืน: ไม่อนุญาต
- การกระจายคำตอบ: สมดุล
- Thai text lock / numeric lock / answer leak guard: เปิดโดยระบบภายใน

หลักสำคัญคือ **Parameter ที่ไม่บังคับต้องไม่ถูกปล่อยค้างแบบไม่ทราบค่า** ระบบต้องกำหนดเป็น Default, Auto/Derived หรือ None อย่างชัดเจน

รายละเอียดเชิงเทคนิคอยู่ใน `policies/PARAMETER_POLICY.md`

# วิธีสั่งงานที่ครูใช้ได้จริง

## แบบที่ 1 — สั้นมาก

> ป.3 เรื่องหาระยะเวลา 10 ข้อ

เหมาะเมื่อครูยอมรับค่าเริ่มต้นทั้งหมด

## แบบที่ 2 — บอกความยาก

> ป.3 เรื่องหาระยะเวลา 10 ข้อ ขอแบบง่าย คำตอบเป็นชั่วโมงเต็ม

## แบบที่ 3 — บอกธีม

> ป.3 เรื่องหาระยะเวลา 10 ข้อ ธีมสวนสัตว์

## แบบที่ 4 — บอกลักษณะงานพิมพ์

> ป.3 เรื่องหาระยะเวลา 10 ข้อ A4 แนวตั้ง ขาวดำ ไม่ต้องมีเฉลย

## แบบที่ 5 — รายละเอียดมากขึ้น

> สร้างใบงาน ป.3 คณิตศาสตร์ เรื่องหาระยะเวลาจากเวลาเริ่มต้นและสิ้นสุด 10 ข้อ ระดับปานกลาง ให้มีทั้งชั่วโมงและนาที ใช้กิจกรรมในชีวิตประจำวัน A4 แนวตั้ง ขาวดำ มีชื่อ ชั้น เลขที่ ไม่ต้องมีเฉลย

ครูไม่จำเป็นต้องเขียนชื่อ Parameter เช่น `ALLOW_MINUTES` หรือ `ANSWER_UNIT_MODE` ระบบจะแปลงภาษาธรรมดาเป็นค่าภายในเอง

# สำหรับครูที่อยากรู้ Parameter

ชื่อ Parameter เป็นภาษาภายใน ไม่จำเป็นต่อการใช้งานปกติ แต่แบ่งเป็นหมวดดังนี้:

1. `EDUCATION` — ชั้น วิชา เรื่อง จุดประสงค์ ความยาก
2. `CONTENT` — จำนวนข้อ ประเภทโจทย์ หมายเลขข้อ เฉลย กิจกรรม
3. `TIME DOMAIN` — รูปแบบเวลา ช่วงเวลา ระยะเวลา ชั่วโมง/นาที
4. `PAGE / PRINT` — A4 แนวตั้ง ขาวดำ จำนวนหน้า ความหนาแน่น
5. `HEADER` — ชื่อ ชั้น เลขที่ ชื่อใบงาน คำชี้แจง
6. `DESIGN` — ธีม เส้นภาพ ตัวละคร กรอบ การตกแต่ง
7. `RENDER SAFETY` — ล็อกข้อความ ตัวเลข จำนวนข้อ ป้องกันเฉลยหลุด
8. `OUTPUT` — จะส่ง Blueprint, QA หรือ Final Prompt แบบใด

สำหรับรายการครบและค่า Default ให้ดู `policies/PARAMETER_POLICY.md`

# Gem ทำงานอย่างไร

ครูไม่จำเป็นต้องทำตามขั้นตอนเหล่านี้เอง ระบบทำให้ภายใน:

```text
คำสั่งของครู
→ ทำความเข้าใจและกำหนดค่า Default
→ วางแผนทักษะและระดับความยาก
→ สร้างคำตอบ/เงื่อนไขก่อน
→ สร้างเวลาเริ่มต้นและสิ้นสุด
→ คำนวณตรวจอีกครั้ง
→ แยกข้อมูลภายในกับข้อมูลที่นักเรียนเห็น
→ ตรวจภาษาไทย
→ ตรวจจำนวนข้อและความซ้ำ
→ วาง Layout และพื้นที่ตอบ
→ ตรวจความเหมาะสมสำหรับพิมพ์
→ สร้าง Final Image Prompt
```

หลักคือ `CONTENT FIRST → VERIFY → LAYOUT → PROMPT → IMAGE`

# ผลลัพธ์ที่ Gem ให้

ค่าเริ่มต้นคือ `PROMPT_PACKAGE` ซึ่งประกอบด้วย:

1. `NORMALIZED_WORKSHEET_SPEC` — ระบบเข้าใจคำสั่งของครูว่าอย่างไร
2. `STUDENT_RENDER_BLUEPRINT` — ข้อมูลที่จะปรากฏในใบงานนักเรียน
3. `LAYOUT_BLUEPRINT` — แผนการจัดหน้า
4. `RENDER_CONSTRAINTS` — สิ่งที่โมเดลสร้างภาพห้ามเปลี่ยน
5. `QA_REPORT` — รายงานตรวจสอบ
6. `FINAL_IMAGE_GENERATION_PROMPT` — Prompt พร้อมใช้สร้างภาพ

เมื่อไม่ขอเฉลย คำตอบที่ใช้ตรวจภายในจะไม่ถูกส่งเข้า Student Render Blueprint หรือ Final Image Prompt

ถ้าครูไม่ต้องการเห็นข้อมูลเทคนิค สามารถสั่งว่า:

> ตรวจทุกอย่างให้เรียบร้อย แล้วส่งเฉพาะ prompt สุดท้าย

---

# หลังได้ภาพแล้วควรตรวจอะไร

แม้ Prompt และโจทย์ผ่าน QA แล้ว Image AI ยังสามารถพิมพ์ภาษาไทยหรือตัวเลขผิดได้ ครูควรดูภาพจริงอีกครั้ง โดยเช็กง่าย ๆ ว่า:

- ชื่อเรื่องถูก
- คำสั่งถูก
- จำนวนข้อครบ
- เวลาในทุกข้อตรงกับ Blueprint
- ตัวอักษรไทยอ่านถูก
- ช่องคำตอบว่าง
- ไม่มีเฉลยหลุด
- รูปไม่ทับข้อความ
- ไม่มีอะไรถูกตัดขอบ
- พิมพ์ A4 แล้วตัวอักษรไม่เล็กเกินไป

ระบบใช้ `HYBRID` เป็นค่าเริ่มต้นสำหรับงานภาษาไทยที่มีข้อความมาก เพื่อให้สามารถแก้/วางข้อความแบบ deterministic เพิ่มภายหลังได้ถ้าจำเป็น

# สิ่งที่ Gem ยังไม่ควรอ้างว่าทำได้สมบูรณ์

ปัจจุบัน `TIME_ENGINE` คือ domain ที่มี validation ชัดเจนที่สุด

โครงสร้างรองรับเงิน การวัด ปฏิทิน ตาราง และโจทย์สถานการณ์ แต่แต่ละ domain ควรมี validation rules และ acceptance tests ของตัวเองก่อนเรียกว่า production-validated

Gem ไม่รับประกันว่า Image AI ทุกตัวจะเขียนภาษาไทยถูก 100% จึงต้องมี post-render QA ก่อนใช้จริง
